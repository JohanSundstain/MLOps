# Данные и препроцессинг

Документ описывает, откуда берутся снимки и эталонные маски, как они превращаются в датасет
патчей, как устроено разбиение на выборки и как всё это версионируется через DVC.

## 1. Источники

### Sentinel-2 L2A (изображения)

- продукт **Level-2A**: bottom-of-atmosphere reflectance, уже атмосферно скорректирован;
- каналы с разрешением 10 м: **B2** (синий), **B3** (зелёный), **B4** (красный), **B8** (NIR);
- значения — целые `uint16`, масштаб 10 000 (то есть `reflectance = value / 10000`);
- доступ: публичный каталог **Element84 Earth Search** (STAC API,
  `https://earth-search.aws.element84.com/v1`, коллекция `sentinel-2-l2a`), сами файлы —
  Cloud Optimized GeoTIFF в открытом бакете `sentinel-cogs` на AWS. Авторизация не требуется;
- альтернатива: Copernicus Data Space Ecosystem (нужен OAuth-токен, поэтому в проекте не
  используется по умолчанию).

Ключевое свойство COG: снимок можно читать **окном по HTTP** (`/vsicurl`, range-запросы), не
скачивая тайл 110×110 км целиком. Именно на этом построен препроцессинг: для AOI читается только
нужный прямоугольник.

### ESA WorldCover 2021 v200 (эталонные маски)

- глобальная карта земного покрова, разрешение 10 м (1/12000°), EPSG:4326;
- класс `80` — **постоянные водоёмы**; он и становится маской «вода»;
- файлы — 3°×3° COG в открытом бакете
  `https://esa-worldcover.s3.eu-central-1.amazonaws.com/v200/2021/map/ESA_WorldCover_10m_2021_v200_<тайл>_Map.tif`;
- имя тайла = нижний левый угол, кратный 3° (`N54E075` покрывает 54–57° с.ш., 75–78° в.д.);
- если AOI пересекает границу тайлов — маска мозаицируется из нескольких файлов
  (`data/worldcover.py::resolve_tiles`).

### JRC Global Surface Water

Используется как источник для валидации и контекста (многолетняя статистика воды), в обучении
не участвует. Упомянут в описании проекта как способ проверки разметки.

## 3. Стадия `download`

```bash
python commands.py download
```

Алгоритм (`data/stac.py`):

1. по AOI и целевой дате формируется окно поиска ±`date_window_days` (45 дней);
2. запрос в STAC с фильтром `eo:cloud_cover < max_cloud_cover` (20 %);
3. отбрасываются сцены, чей bbox не покрывает AOI целиком (частичное покрытие на краю витка);
4. сортировка: сначала меньшая облачность, затем близость к целевой дате;
5. берётся лучшая сцена, проверяется наличие всех нужных assets (4 канала + SCL);
6. для каждой сцены читается маленькое окно каждого asset (проверка доступности);
7. результат пишется в `data/raw/scenes_manifest.json` — единственный «вход» препроцессинга.

Если для AOI нет подходящей сцены, по умолчанию печатается предупреждение и AOI пропускается
(`data.stac.strict=true` — падать).

## 4. Стадия `preprocess`

```bash
python commands.py preprocess
```

### 4.1. Окно AOI на сетке сцены

`data/scenes.py::compute_aoi_window`:

1. bbox в EPSG:4326 переводится в CRS сцены (UTM) через `rasterio.warp.transform_bounds`;
2. границы расширяются до целых пикселей 10 м (`snap_bounds_to_grid`) — чтобы AOI всегда
   начинался на границе пикселя и результат не зависел от округления;
3. из границ строится `Window`, который обрезается по границам сцены.

### 4.2. Чтение каналов и SCL

- 4 канала читаются окном (`boundless=True`, `fill_value=0`) и складываются в массив
  `(4, H, W)` `uint16`;
- **SCL читается в своём окне и своём разрешении**: это 20 м, поэтому окно считается от тех же
  географических границ, но на сетке SCL, а затем ресемплится к `(H, W)` методом nearest. Это
  важный момент: если читать SCL по окну 10-метрового канала, покрывается только четверть
  площади и маска валидности получается мусорной;
- валидность: `~isin(SCL, [0,1,3,8,9,10,11])` — нет данных, дефекты, тень облака, облака,
  перистые облака, снег; дополнительно отбрасываются пиксели с reflectance 0;
- если SCL в сцене отсутствует — все пиксели считаются валидными (с предупреждением).

### 4.3. Маска воды

`data/worldcover.py::read_water_mask`:

1. берутся все тайлы WorldCover, пересекающие AOI;
2. для каждого открывается окно, покрывающее сетку сцены, и репроецируется на неё
   (`Resampling.nearest`, классы нельзя интерполировать);
3. вода = `class == 80`;
4. ведётся счётчик покрытия: если какие-то пиксели не покрыты ни одним тайлом, пишется
   предупреждение (они считаются сушей).

Согласованность проверена количественно: IoU маски WorldCover с водой по NDWI на снимке Чаны
(2024) — **0,946**, на Новосибирском водохранилище — **0,954**, и максимум достигается при
нулевом сдвиге, то есть систематического смещения нет.

### 4.4. Нарезка на патчи

- массив дополняется до кратности 256 (`pad_to_multiple`, режим `edge`), невалидная область
  помечается `False`;
- патчи режутся с шагом `data.patch.stride` (по умолчанию 256, то есть без перекрытий);
- для каждого патча считаются `water_fraction` (доля пикселей воды) и `valid_fraction` (доля
  облачно-свободных пикселей).

Отбор (`data/patches.py::select_candidates`):

| Правило                                                    | Значение в конфиге | Зачем                                                                                             |
| ---------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------- |
| `valid_fraction ≥ min_valid_fraction`                      | 0,95               | не учиться на облаках                                                                             |
| `min_water_fraction ≤ water_fraction ≤ max_water_fraction` | 0,02 … 0,98        | убрать полностью водные и полностью сухие патчи: первые ничего не дают, вторые нужны как негативы |
| доля негативов `negative_ratio`                            | 0,30               | модель не должна «видеть воду везде»                                                              |
| `max_patches_per_scene`                                    | 18                 | ограничить размер датасета и стоимость чтения                                                     |

Отбор негативов и подвыборка позитивов используют `np.random.default_rng(stable_seed(seed,
aoi, date))` — детерминированно и воспроизводимо между процессами (встроенный `hash()`
солится `PYTHONHASHSEED` и для этого не годится).

### 4.5. Разбиение на выборки

`data/splits.py` — **групповое** разбиение по озёрам (все патчи одного озера в одном сплите),
иначе соседние патчи одного снимка утекают между train и test.

Как выбирается, какие озёра уйдут в val/test:

1. список групп детерминированно перемешивается (`seed`);
2. целевые доли пересчитываются в **число озёр** (70/15/15 от 12 → 8/2/2);
3. если известны размеры групп (число патчей), выполняется точный перебор всех вариантов
   «какие 2 озера в val, какие 2 в test» и выбирается комбинация с минимальной суммой квадратов
   отклонений от целевых долей (при ≤ 24 озёрах это тысячи вариантов, считается мгновенно);
4. для большего числа озёр используется жадный алгоритм.

Результат на текущем датасете — **309 / 66 / 66 патчей (70,1 % / 15,0 % / 15,0 %)**:

| Сплит | Патчей | Озёра                                                                                   |
| ----- | ------ | --------------------------------------------------------------------------------------- |
| train | 309    | burlinskoye, ob_reservoir, omsk_ik, sartlan, sladkoye, teletskoye, topolnoye, ubinskoye |
| val   | 66     | bol_yarovoye, itkul_altai                                                               |
| test  | 66     | chany, shira                                                                            |

### 4.6. Нормализация

`data/normalization.py`:

```
reflectance = clip(value / 10000, 0, 0.4)            # физически разумный диапазон
normalized  = (reflectance - mean_train) / std_train # по каналам, статистики только train
```

Статистики считаются по всем пикселям train-сплита и сохраняются в
`data/processed/norm_stats.json`, а затем попадают в `bundle.json` — инференс никогда не
пересчитывает их по своим данным (это была бы утечка).

## 5. Формат датасета

```
data/processed/
├── patches/<aoi>__<date>__r<row:05d>_c<col:05d>.npz   # image uint16 (4,256,256), mask uint8 (256,256)
├── manifest.csv                                        # 441 строка
├── norm_stats.json
└── dataset_summary.json                                # сводка + полный конфиг
```

Колонки `manifest.csv`:

| Колонка                                                    | Смысл                                       |
| ---------------------------------------------------------- | ------------------------------------------- |
| `patch_id`                                                 | `aoi__дата__rстрокой_cколонкой`             |
| `path`                                                     | путь к `.npz` относительно `data/processed` |
| `split`                                                    | `train` / `val` / `test`                    |
| `aoi`, `group`                                             | озеро и группа сплита                       |
| `target_date`, `scene_id`, `scene_datetime`, `cloud_cover` | происхождение патча                         |
| `row`, `col`, `patch_size`                                 | позиция в сцене                             |
| `water_fraction`, `valid_fraction`                         | статистики отбора                           |
| `crs`, `crs_epsg`, `transform_a…f`                         | геопривязка патча (нужна для площади)       |

`dataset_summary.json` содержит число патчей, доли сплитов, соответствие «озеро → сплит»,
статистики нормализации, список сцен со статусами и полный конфиг запуска.

## 6. Контроль качества

- **`plots/dataset_preview.png`** — по 3–4 патча с береговой линией: снимок (RGB), маска,
  наложение. Визуально видно, что маска совпадает с водой.
- **Количественная сверка** — IoU маски WorldCover против NDWI на снимке (см. 4.3).
- **Сводка** — `python commands.py dataset-info`: сколько патчей, какие озёра в каких сплитах.

Известные ограничения разметки (важно для интерпретации метрик):

1. WorldCover описывает **постоянные** водоёмы 2021 года; на снимках 2023–2024 пересыхающие
   солёные озёра выглядят иначе, поэтому часть «ошибок» модели — это расхождение дат, а не
   ошибки модели;
2. класс воды включает реки и водохранилища, не только озёра;
3. облака и тени удаляются фильтрами, но остаточные артефакты возможны (порог `valid_fraction`
   не 100 %);
4. сезонность: уровень воды в июле 2023 и июле 2024 различается естественным образом.

## 7. Версионирование данных (DVC)

`dvc.yaml` описывает три стадии:

```yaml
stages:
  download:   cmd: python commands.py download    outs: [data/raw/scenes_manifest.json]
  preprocess: cmd: python commands.py preprocess  outs: [data/processed]
  train:      cmd: python commands.py train       outs: [weights]
```

Правила:

- в git попадают только метаданные (`dvc.yaml`, `dvc.lock`, `data/example.dvc`) и код;
- данные и веса лежат в DVC-кэше и удалённом хранилище (по умолчанию локальный каталог
  `../sentinel2-lake-dvc-storage`, можно переключить на S3/Google Drive);
- `commands.py train` и `infer` при отсутствии `data/processed` сами вызывают `dvc pull`
  (`data/dvc_utils.py`), а если хранилище недоступно — `train` пересобирает датасет из
  открытых источников (`train.auto_preprocess=true`).

Типичные команды:

```bash
dvc repro            # пересчитать стадии, у которых изменились входы
dvc push             # отправить данные и веса в хранилище
dvc pull             # забрать их на новой машине
dvc status           # что устарело
dvc remote modify storage url /path/to/shared/storage
```

| Объём чтения из сети              | ≈ 400 МБ (только окна AOI, не тайлы целиком) |

## 9. Как изменить данные

- **Добавить озеро**: дописать запись в `data.aois` (`name`, `bbox`, `dates`, при необходимости
  `group`). Проверить, что bbox внутри одного тайла Sentinel-2 и одного тайла WorldCover 3°
  (иначе маска соберётся из нескольких файлов — это поддерживается, но лучше проверить визуально).
- **Другие даты**: изменить `dates` у AOI; сцена подберётся автоматически в окне ±45 дней.
- **Больше/меньше патчей**: `data.patch.max_patches_per_scene`, `min_water_fraction`,
  `negative_ratio`.
- **Другая разметка**: заменить `read_water_mask` на свой источник, сохранив контракт
  «сетка сцены → bool-маска».
